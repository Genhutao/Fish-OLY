01

三条不变量

后面的所有模块都在服务这三条。任何设计如果让其中一条失效，就是错的，不管它看起来多优雅。

INVARIANT 01 事件先于状态

世界里的每一次变化先写一条事件，再由事件派生房间、角色、关系的当前值。事件是史记，读模型只是缓存。

INVARIANT 02 记忆是派生物

槽向量不是真相，成员原文才是。向量由成员重算，成员由事件重放。所以回滚的粒度是「一条成员」，不是「一次写入」——这个差别决定了记忆能不能被真正撤销。

INVARIANT 03 每次调用都要有理由

模型调用不是 tick 的默认动作。先算发言权，过阈值才装配上下文；没过就只更新状态，并记录「它选择沉默」。

03

世界循环

一拍不是「所有角色都说话」，而是「所有角色都发生变化，只有一两个开口」。中间三步全在本地完成，不烧 token。

发言权怎么算

attention = 0.35·被@ + 0.25·话题相关 + 0.20·关系强度 + 0.10·紧急度 − 0.20·精力成本 + ε
// 全部来自本地可读字段：消息、标签、affinity、energy。不调模型。
// ε 是少量噪声，防止同一批角色每次都以同样顺序开口。

阈值之上按分数排序，房间层再加冷却与轮转，保证同一角色不会连续刷屏。沉默不是没有输出——它是一条事件，会进反思阶段，影响下一次的日程。

什么时候真的要模型

档位用在哪约束
规则发言权、精力、换场、冷却纯本地，微秒级。任何时候都不许为了「更像活的」把它换成模型。
cheap 判定过阈值后的二次确认、摘要、打标一次几十 token，只输出第一行的 [说] / [不说]；缓冲 48 字符即判定，用户看不到这段。
main 生成单聊、剧情、被判定要说话的群聊完整提示板，带记忆与状态；失败要显式报错，不许静默降级成模板台词。
judge 评测离线：人格记分卡、记忆召回不进线上链路，按周跑，出数字。
04

记忆

这一层沿用 VSA 的形态：16384 位超向量、六层分槽、纯整数运算。它不是「向量库」，是可解释、能离线跑的记忆体——但撤销粒度得我们自己补一层。

六层，分开检索

层存什么权重OLY 里的例子

检索打分

base = sim × decay × (0.6 + 0.1·imp) × layer_w
decay = 0.5 ^ (age / S)，S = 30 × clip(imp, 0.8, 4)，age 按 last_day 算
score = max(base, tag_score) + 1e-3·base // 标签与词面取强者，不相加

三个细节决定成败：衰减从原始重要度 imp0 算、不写回；被重新提起就刷新 last_day，天天说的事不该自然死亡；标签只做「词面零重合」时的保底，永远不许压过强词面匹配。

写入与巩固

写入事件 → 规则抽取（18 类标签）→ 审查 → 查重：>0.92 合并、>0.62 追加同槽、否则开新槽
单槽上限最多 6 条绑定。宁可多开槽，不可串台——全捆是这条路唯一被判死的走法
夜间巩固合并 → 升降权 → 遗忘，顺序不可换。合并是遗忘的前置条件
和现在 Demo 的关系：当前是「一个角色一个数组 + 32 维字符直方图」，正是 VSA 已经证伪的全捆形态。换掉它不是优化，是纠错。

回滚粒度：成员是真相，向量是缓存

VSA 的 write() 走 merge / append 时是 vec = bundle([prev, new])。bundle 是多数投票，天生不可逆：一条错记忆并进槽之后，你没法把它从向量里减掉。所以这里必须改数据模型，不能靠加一个 undo 接口糊过去。

洞VSA 现状本设计怎么补
写入不可逆bundle() 直接改写槽向量，没有旧值可退成员单独存；槽向量由成员集合重算，撤回一条是「重算」而不是「相减」
墓碑粒度错位forget() 标的是槽（sid）。一槽最多 6 条，错 1 条连带屏蔽 5 条对的墓碑下沉到成员级；槽内成员全撤，槽才消失
权重没留痕merge 用 1:1、append 用 3:1，历史权重没记，事后重放不出原向量每条成员带自己的权重 w，向量 = bundle(member × w)，是纯函数
编码器漂移换编码器或种子，旧向量再也算不出来库内固化 encoder_version 与 bundle_rule_version；一变更就整库重建，并记一条迁移事件
为什么必须现在定：「用户说这不是真的」是记忆产品的底线功能。等库里有十万条槽再改，重建规则就成了一次数据迁移事故。改成纯函数之后，巩固、合并、遗忘都只是对成员集合的编辑——可逆、可审计、可重放。

唯一要知道的代价：定义变了，同一批记忆的分数会和 VSA 现有实现有微小偏差。所以移植完必须先跑 120 题回放，确认 Recall@5 不掉，再往下做。

06

七个设计决策

每个决策都写清楚「为什么不是另一种」。这些是后面写代码时最容易被悄悄改掉的地方。

01

记忆放在本地进程里，不做 sidecar

VSA 是纯整数位运算，没有模型、没有外部依赖。把它搬进宿主进程，一次检索是微秒级；挂成 Python 服务则每拍两次 IPC，还要多带一个运行时。

代价：要重写一份内核；对冲：用 VSA 现成的 120 题回放做验收，Recall@5 必须落在 0.70 以上，偏了就是移植错了。

02

群聊走「本地打分 + 便宜模型确认」两段式

第一段纯规则算 attention，第二段只对过线的角色做一次几十 token 的判定。Arc 那边已经证明这条路可行：先输出一个标记，网关缓冲到第一个换行再决定要不要转发给大模型。

为什么不直接每个角色都调模型：20 人房间每拍 20 次调用，成本与延迟都不可接受，而且大多数角色本来就该沉默。

03

世界数据用事件表，不用「当前状态表 + 定时快照」

重启后世界还在，靠的是 events 重放，而不是把 map 序列化到磁盘。事件同时喂给记忆抽取、审计、回放和评测。

代价：读模型要维护投影；收益：任何一条记忆都能回答「你从哪句话记住的」。

04

情绪是状态机，不是提示词里的一句话

E(t+1)=0.8·E(t)+0.2·ΔE，情绪向量再反推 temperature、回复长度区间、反问概率。同一句「我没事」，受伤时该短、该冷、该不追问。

为什么不用 mood 字符串：字符串只能写进提示词，改不了检索排序，也没法做「今天和昨天不一样」的回归测试。

05

只有单聊 / 剧情 / 过线群聊打模型，漫游永远不打

漫游是状态机加模板，它的价值在「一直在动」，不在措辞。把模型留给用户真正看的地方。

如果哪天要给漫游接模型：先做「事件 → 摘要 → 写记忆」的离线任务，让角色记得昨天去过哪，而不是实时生成动作描写。

06

先模块化单体，不拆服务

一个进程、按域分包、跨域只发事件。接口层保持 Wails 绑定不变，前端一行不用改。

拆服务的时机：单世界并发或多人协作成为瓶颈时。现在拆，只会把调试成本乘以进程数。

07

槽向量是成员集合的纯函数，不是写入历史的累积

bundle 是多数投票，天生不可逆。所以真相放在成员层：每条记忆是一条不可变的成员记录，槽向量每次由成员重算。撤回一条 = 从集合里去掉一条 + 重算，不是对向量做减法。

代价：和 VSA 现有分数会有微小偏差，得用 120 题重跑确认召回不掉；收益：墓碑、撤销、巩固全都退化成集合编辑，可逆、可审计、可重放。

07

现有资产怎么接

三份东西各有各的位置：VSA 给记忆，Arc 给路由思路，OLY 给界面与世界。不要试图把它们合成一个框架。

资产真正有用的部分在架构里的位置
VSA 内核 超向量原语、六层分槽、查重阈值、衰减公式、巩固三件套 memory 域的全部实现。Python 与 TS 两份参考实现可以逐条对照移植。
VSA 评测 120 题数据集、Recall@5 / MRR / 误记忆率、人格记分卡 不进产品，进 CI 与周报。这是判断「记忆有没有变差」的唯一尺子。
Arc 的网关 首行标记 + 缓冲判定、两份上下文投影、工具痕迹索引 借思路写进 runtime 的判定器与装配器。不搬代码，也不套一层网关。
Arc 的日记 按年/月/周落盘的日记体，人可读 导出层。世界史给人看的样子，不当主存储。
OLY 现有前端 13 个路由、双主题、技能库、设置页 原样保留。所有改造都在后端与数据层，界面只多两个入口：世界史、记忆库。

风险与不做

风险表现对策
成本失控多角色持续对话 token 暴涨发言权闸门 + 三档模型 + 摘要压缩；按世界核算每百条消息成本。
