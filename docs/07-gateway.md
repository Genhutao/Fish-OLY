# 07 · 模型网关

LLM 调用的独立分片域：全部模型流量（角色决策、归纳批处理、储备预生成、用户直连功能）唯一入口。会话 loop 对其只做 `co_await submit/reply`，永不阻塞。

## 1. 域结构与供应商适配

```
GatewayShard × g（独立 loop 池）
  优先级队列 × 4 类
  Provider 适配器 × 多（LLMProvider 接口 = 插件扩展点之一，见 12）
  成本台账 / 配额桶 / 熔断器 / 饱和度估计器
会话 loop ──submit(request)──► 网关 ──reply/failure──► 会话 loop（channel 回传）
```

- 请求携带：任务类别（决定档位）、提示板引用、max_tokens、deadline、取消槽、trace；
- 上游流式响应在网关聚合；需要打字机效果的会话可将 chunk 转推订阅者（决策/tool_calls 仍以最终结果为准）。

## 2. 优先级与削减

| 级 | 类别 | 例 |
|---|---|---|
| P0 | 交互（用户在等） | 用户触发对话、直连模型功能 |
| P1 | 剧情 | 导演驱动的关键演绎 |
| P2 | 环境闲聊 | 自治发言、储备预生成 |
| P3 | 归纳批处理 | 摘要、事实抽取、重要度重算 |

挤兑自底向上削减：P3 → P2 →（会话侧降档/储备兜底）。**P0 永不丢**。

## 3. 预留-结算协议

```
submit 时按 prompt 大小 + max_tokens 预估 → 各配额桶预留（09 §3）
响应到达 → 真实用量结算：多退少补 → cost.recorded 事件
决策超时/取消 → 预留随 deadline 到期自动释放（无悬挂占用）
```

## 4. 饱和度反馈闭环（全局稳态控制器）

```
饱和度 s ∈ [0,1]（队列深度 + 延迟分位 + 配额水位）定期广播至进程流
  → 各会话 loop 反馈调节：
      s ↑ → τ_speak 上调、tick 周期拉长、归纳更激进批化
      s ↓ → 逐步放开
  → 世界预算将尽同理：角色群体性"今日话少"，而不是报错
```

自治频率不是静态参数，而是被网关饱和度与配额水位实时驱动的控制变量。

## 5. 熔断与降档

- 每 `(tier × provider)` 维护滑动窗口失败率；超阈 → 熔断，流量切低档 tier；
- 半开探测恢复；熔断状态事件进进程流（运维可见）；
- 档位路由规则：任务类别默认档 + 世界/主体配置覆盖（08）+ 饱和度强制降档。

## 6. 批处理

- 归纳类（摘要/抽取）合并多会话为一次大调用（分段标记），P3 档；
- 储备预生成批量出题（一次调用生成一角色一组台词）；
- 批处理只在配额闲时窗口执行（水位低时）。

## 7. 成本台账

```
cost.recorded(actor, on_behalf_of, tier, provider, tokens{in,out},
              request_ref, world_ref)   —— 唯一记账事实（网关域产出）
  → 按主体树逐层聚合（09 §6）、按世界聚合、按供应商聚合
  → 配额强制、账单视图、审计
```

不做语义回复缓存（角色一致性风险大于收益）；供应商原生前缀缓存可用则用（对业务透明）。

## 8. 容量锚点

以 06 §6 走查为基准：百会话世界 ≈ 16 决策/秒 + 批化归纳。单网关分片目标 ≥ 2k 并发在途请求；分片数按目标世界数线性扩展。网关是成本与负载的第一瓶颈，饱和度闭环保证过载时**降质不降可用**。
