# 01 · 执行内核

## 1. 线程模型：thread-per-core + 世界级单写者

无锁的实现路径是**所有权与消息传递**，而不是 lock-free 算法：让可变数据不跨线程。

```
进程
├── loop-0 .. loop-N-1   N = 核数；每线程一个 asio::io_context
│     会话按 shard 绑定到 loop（单写者域）
├── 身份分片执行器（按 principal_id hash 分片；M0 可 1 片）
├── 模型网关域（独立 loop 池）
├── db/tiering 池（阻塞 IO 封装为 awaitable；预留 libpq 非阻塞模式）
└── 接受器/会话循环（WS 连接，独占其 socket 线程）
```

- **一个会话的全部领域状态**（成员 presence、工作集、tick 计数、输入队列、读模型）只被其绑定 loop 上的协程触碰 → 会话内部**零锁、零原子变量、零 shared_ptr 竞争**。
- **身份域**可变状态只属于其分片执行器；与会话域之间仅通过命令事件与通知事件交互。
- 跨 loop 通信只有两种形态：**有界通道**（move-only 消息）与**只读版本化内容**（卡片/Canon/配置 blob，I3 允许的例外）。
- **Shard（分片）**是调度与存储的共同所有权单元：一组流 + 其段文件 + 一个绑定 loop；多节点部署时 shard 整体迁移到目标节点（05 §7）。会话/身份到 shard 的映射即路由表，存进程流。

### 会话与 loop 的绑定

- 绑定信息（session_id → loop）存进程流；仅在创建/迁移时变更。
- **会话迁移协议**（io_context 绑定可变；与启动重放同一份代码）：
  1. 目标 loop：从快照 + 段文件重放到当前 seq（预热）；
  2. 原 loop：停止消费，未消费输入随游标移交；
  3. WS 订阅重接到目标 loop；
  4. 写 `session.migrated` 事实事件，原侧析构。
- 负载均衡 = 周期性依据 loop 负载指标（队列深度、CPU）做 shard 重分配，走同一迁移协议。

## 2. 中央轮式 tick 调度器

不使用"每会话一个定时器"（十万级句柄、O(log n) 插入不可接受）。

```
每 loop 一个 hierarchical timing wheel：
  分辨率 100ms、一圈 2048 槽
  会话按"下次 tick 截止"入槽 → 指针 O(1) 前进 → 整槽到期会话批量出队
  → 对每个到期会话投递一个 tick 输入（协程 resume）
```

- 20 万会话 × 每 4s 一拍 ≈ 5 万次 tick resume/秒，单轮余量充足。
- **导演交互**：暂停 = 摘除该会话的轮槽；单步 = 投递 1 个 tick；加速 = 缩短该会话 tick 间隔。
- **过载合并**：会话队列积压时允许跳拍（虚拟时钟落后墙钟），这是优雅降级而非故障。

## 3. 会话输入队列：两车道

```
interactive 车道：用户命令、LLM 回复、导演指令 —— 绝对优先
background 车道：自治 tick、环境事件、归纳任务、反思回调
```

过载降级顺序固定：**拉长自治 tick 周期 → 砍背景事件 → 用户命令永不丢**（有界队列 + 准入限流 + 幂等重试）。

## 4. 背压点（全部有界）

| 通道 | 界 | 超限策略 |
|---|---|---|
| WS 会话入口 | 每连接 | 429 / 短暂断开（携带 last_seq 供续传） |
| 会话输入队列 | 每会话 | interactive 阻塞准入（限流），background 丢弃低优 |
| 模型网关提交 | 每网关分片 × 优先级 | P3→P2 自底削减；P0 永不丢 |
| 出站每订阅者 | 每订阅 | 服务端断开并携带续传游标（见 10-api） |

### 4.1 瞬态信令

输入中指示、在线状态等实时信号**不进入事件日志**：由会话 loop 直接沿 WS 订阅广播，零持久化、零 seq 消费。事件流的可重放性不因信令破坏（重放世界不含信令）；协议见 10 §5。

## 5. 批处理纪律（吞吐与延迟的全部来源）

1. **唤醒即批**：每次事件循环唤醒 drain 队列至多 K 条，批量处理而非逐条。
2. **扇出零拷贝**：一条出站事件 = 一块引用计数缓冲，同一会话的所有订阅者共享（广播路径零复制、零分配）。
3. **写合并**：同一 WS 连接的多条事件在每轮合并为一次 `writev` / 多缓冲发送。
4. **内存**：每 loop 私有对象池 + 载荷 arena；热路径无全局分配、无 shared_ptr；协程帧走 asio per-thread allocator 钩子；跨 loop 消息 move-only。
5. **网络后端**：Linux 生产 io_uring，Windows 开发 IOCP，同一套协程代码。

## 6. 协程纪律

- 使用 Boost.Asio `awaitable<T>` + `co_spawn`；不引入 cppcoro。
- 生命周期铁律：`co_await` 目标生存期 ≤ 所在 loop；WS 会话用弱句柄 + 代数计数防悬挂。
- **每个外部 `co_await` 必须有超时 + 取消槽**（asio cancellation_slot）：会话卸载/暂停/导演接管即批量 cancel。
- **监管者模式**：自治决策协程一律经 supervisor `co_spawn`；异常 → 记事件 → 从上次已提交 seq 恢复状态（内存中不存在不可重构的状态）。
- 领域协程禁止：递归 co_spawn 无上限、无超时等待、跨 loop 直接改共享对象。

## 7. 调度预算（设计校准数字）

| 项 | 数字 |
|---|---|
| 协程空转 resume | ~100–300 ns |
| 带实际工作 resume | ~0.5–2 µs |
| 单 loop 调度能力 | 10万–30万 次带工作 resume/秒 |
| 16 loop 合计 | 160万–480万 次/秒（对目标量级 ≥2 倍余量） |
| 打分内核（20 人会话一拍） | <1 µs，零分配（见 06） |

## 8. 编译与标准

- C++20；C++23 特性（`std::expected`、`std::move_only_function` 等）以编译器探测宏门控。
- MSVC 19.4x 优先（开发平台 Windows），CI 覆盖 GCC 13+ / Clang 17+（生产 Linux）。
- 每个 domain 模块一个独立静态库 target，物理隔离依赖方向；禁止反向 include（用 CMake 依赖图 + CI 检查强制）。

## 9. 允许存在的锁（白名单）

| 位置 | 保护对象 | 触碰频率 |
|---|---|---|
| 路由表 rwlock | session/principal → loop/shard 映射 | 仅创建/迁移 |
| 生命周期管理 | 进程启停、loop join | 一次性 |
| 指标计数 | atomics | 高频（无竞争写） |

领域数据永远不碰锁。任何 PR 引入白名单外的锁需架构评审。
