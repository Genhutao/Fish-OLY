## 1. 定位

OLY 世界引擎是一个**服务器端**系统：让用户用会话搭建世界、让角色（AI Persona）按自己的设定在世界中自主生活、社交与演绎。客户端（桌面 / 移动 / Web）为独立工程，**API 契约是本引擎的第一交付物**。

一句话：**用会话搭建世界，让每个角色按自己的设定生活。**

## 2. 四条核心命题

1. **会话即世界**：世界观（Canon）冻结在会话上；成员在其中发言、行动、演绎；单聊与群聊同构。
2. **角色自主**：角色不是对话框里的回复器，而是运行"感知 → 评估 → 意图 → 行动 → 反思"循环的主体；**沉默也是行动**，**成本是硬约束**。
3. **一切皆事件**：世界的唯一真相是事件流；状态、消息列表、记忆、配置全部是事件的可重建投影。这天然带来审计、回滚、重放、推演与增量同步。
4. **用户与角色同地位**：统一为主体（Principal），同一套所有权、可见性、权限与配额；角色的一切能力经由工具调用表达，一切行动发生在会话内。

## 3. 设计公理

| # | 公理 | 直接后果 |
|---|---|---|
| A1 | 用户与角色统一为主体：均有 ID、创建者、可见性、权限、可用工具集 | 一套权限/所有权/配额模型 |
| A2 | 角色 = 纯设定（卡片） + 会话内活动；定义与语境分离 | 卡片版本化、可共享、可导出；角色无全局自由活动 |
| A3 | 会话是运行单元：持有不可变世界观 + ≥2 成员 + 一个 io_context 绑定（可迁移） | 世界观不一致从结构上消灭；会话是唯一有状态调度域 |
| A4 | 一切能力皆工具；用户命令与工具调用统一为命令事件 | 权限/审计/配额/插件化单点生效；角色保持薄 |
| A5 | 记忆归属于与角色互动的主体；跨会话；分短期/长期两层 | 共享角色对不同主体有不同记忆分册 |
| A6 | 权限树形继承：创建者对其 creations 拥有全部权限（超集）；配额树对偶：子节点分配之和 ≤ 父节点（见 09） | 权限检查 = 纯函数；资源树向下被包含 |

## 4. 结构不变量（进 CI 的类型注释 + 运行时断言）

- **I1** 会话成员 ≥ 2；单聊与群聊同一类型，差异只在成员数与权限模板。
- **I2** 角色的**决策**只发生在会话内；决策产生的管理类命令路由到身份域流执行。
- **I3** 领域可变状态只属于其会话的 loop；`Principal` / `PersonaCard` / `Canon` / 配置内容为不可变或版本化数据，是唯一允许的跨线程只读共享。
- **I4** 创建者对对象的有效权限 ⊇ 任何其他主体；会话内 Owner ⊇ Admin ⊇ Member。
- **I5** Canon 冻结（不可变内容）；事件流是唯一可变历史；摘要/事实/向量/记忆皆为可重建的派生层。
- **I6** 每个对象有 ID；每个写操作是一条事件；每条事件可溯源（causality 链）。

## 5. 目标量级（设计靶子，所有模块按此校准）

| 指标 | 单盒目标 |
|---|---|
| 并发活跃会话 | 5万 – 20万 |
| 事件吞吐（持久化） | 100万 – 200万 事件/秒 |
| 消息端到端延迟 | p99 < 50ms（fsync 窗口 2–10ms 为下限项） |
| WS 长连接 | 每盒 10万 – 30万 |
| 线程数 | = 核数（thread-per-core），单线程调度数万会话 |
| 集群 | shard 为水平扩展单元；primary-backup 日志复制 |

## 6. 顶层架构

```
客户端（独立工程）
   │ REST（命令/查询）        WS（事件订阅/推送）
   ▼
┌─────────────────────────────────────────────────────────┐
│ 接入层：REST 网关 · WS 会话管理 · 鉴权 · 全局限流 · 幂等    │
├─────────────────────────────────────────────────────────┤
│ 执行层：loop × N（thread-per-core，每线程一个 io_context）│
│   ├ 会话 loop × k：会话单写者域                          │
│   │    有界输入队列（两车道）· 轮式 tick 调度器           │
│   │    估分内核 → 决策协程（提示板→网关→工具循环）        │
│   │    执行（命令→事实事件）→ 反思（后台车道）            │
│   ├ 身份分片 × s（按 principal_id hash）：               │
│   │    卡片版本链 · 关系绑定 · 授权边 · 配额树 · 审阅覆盖 │
│   └ 模型网关域（独立 loop 池）：                          │
│        优先级队列 · 预留-结算 · 熔断降档 · 成本台账       │
├─────────────────────────────────────────────────────────┤
│ 存储层（log-first 三层）                                 │
│   第0层 内存投影（服务真相，读全部走内存）                │
│   第1层 本地段文件（持久真相：组提交 fsync，哈希链）      │
│   第2层 PostgreSQL/对象存储（异步归档、查询索引，不在线上）│
└─────────────────────────────────────────────────────────┘
```

## 9. 术语表

| 术语 | 定义 |
|---|---|
| Principal 主体 | 用户或角色的统一抽象：ID、创建者、可见性、权限、配额 |
| Persona 角色 | 可被扮演、可自主行动的主体；定义=卡片，运行态=会话内 presence |
| Card 卡片 | 角色的纯设定（版本化、内容寻址）；脱离语境即一份数据 |
| Session 会话 | 世界观 + ≥2 成员 + 权限层级 + loop 绑定的运行单元 |
| Canon 世界观 | 会话持有的不可变设定内容（内容寻址 blob） |
| Member 成员 | 主体在会话内的成员关系：角色（Owner/Admin/Member）+ presence |
| Presence 在位状态 | 成员在会话内的运行态：精力/心情/日程/工作集 |
| Binding 绑定 | 主体对角色卡片的版本装订：FollowHead 或 Pin(version) |
| Fork 分叉 | 从会话历史某点派生新时间线；用于推演不同结果 |
| Stream 流 | append-only 事件通道：会话流 / 身份流 / 进程流 |
| CommandEvent 命令事件 | 变更意图（用户操作、角色工具调用、导演注入、系统） |
| FactEvent 事实事件 | 命令执行产生的不可变状态变更 |
| Prompt Board 提示板 | 按槽位与 token 预算装配 LLM 上下文的组件 |
| Deliberation 决策 | 角色一次"感知→…→行动"的完整协程生命期 |
| Director 导演 | 世界控制者：暂停/单步/注入/回滚/解释 |
| Gateway 模型网关 | LLM 调用的独立分片域：路由、配额、成本、降级 |
| Visit 串门 | 角色以访客身份进入另一会话（M2+） |
| World 世界 | 以同一 Canon 为世界观的会话族（模板实例与 fork 族）；世界级配置与预算的挂载层，**不是独立运行实体** |
| Shard 分片 | 调度与存储的共同所有权单元：一组流 + 其段文件 + 绑定 loop（多节点时绑定节点） |
| Signal 瞬态信令 | 不入事件日志的实时信号（输入中、在线状态）；仅广播，零持久化，不占 seq |
| Attention 发言权 | 角色在当前事件下的加权评分；低于阈值即沉默 |
