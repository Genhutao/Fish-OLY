# 09 · 配额与限流

配额树与权限树对偶：**权限树是控制权向下超集（创建者管一切），配额树是资源向下被包含（子节点分配之和 ≤ 父节点）**。

## 1. 资源总账

| 类别 | 资源 | 计量 | 主要消费方 |
|---|---|---|---|
| 模型计算 | token（分档）、请求速率、并发决策数 | token / 次 / 计数 | 角色 deliberation、归纳、用户直连功能 |
| 存储 | 记忆条目数、blob 字节数 | 条 / 字节 | 记忆管线、卡片版本 |
| 实体 | 拥有角色数、拥有会话数、单会话成员数、卡片版本深度 | 计数 | 创建类命令 |
| 社交保护 | 邀请速率、dm_request 速率、发言突发速率 | 次/窗口 | 防骚扰/防刷（**平台包络，不可配置**） |
| 扩展 | 插件/外部工具调用速率、fork/沙盒次数与 token | 次 / token | 技能执行、推演（M2） |
| 连接 | WS 并发连接数 | 计数 | 客户端 |

## 2. 配额树

```cpp
struct QuotaNode {                    // 挂在 principal 树每个节点上
    Limit     self_limit;             // 自身消费硬顶（父授或平台授）
    vector<Allocation> children;      // 向下分配
    Overage   overage_policy;         // 超限策略（配置面 08）
    // 不变量：Σ children.allocation ≤ self_limit   （准入强制）
};
```

- 平台 → 链根用户：按订阅档位授予（`quota.granted` 事件，商业挂接点）；
- 用户 → 其创建的角色：分配隔离（防一个失控角色烧穿全部预算）；
- 角色 → 其创建的角色：分配可继续下传，链式受限；
- 分配动态可调（`quota.allocate` 身份流命令，权限=分配者），已消费不回收、影响下一窗口；在途预留按旧分配封顶；
- **世界是第二维度**：世界 token 预算挂载于 canon（世界 = 同 canon 会话族，Owner 设定）。一次花费的实际可用量 = **min(树上各层剩余, 世界预算剩余)**，任一处触顶即受限。

## 3. 限流机制

### 3.1 两层桶（每 `主体节点 × tier × 维度` 一组）

- **突发桶**（token bucket：速率+容量，秒级）——防瞬时挤兑；
- **体量配额**（日/月窗口）——成本控制，用户可感知、可分配。

### 3.2 预留-结算（token 事后才知道真实值）

```
gateway.submit：按 prompt+max_tokens 预估 → 各层桶预留
响应到达：真实用量结算，多退少补 → cost.recorded
决策超时/取消：预留随 deadline 到期自动释放
```

### 3.3 租约制（量级关键优化）

会话 loop 不做每次跨域查桶：

- 高频小限（发言突发、命令速率）由 quota 分片按**租约**批量下发到 loop 本地桶，本地消费、异步续租对账；
- 硬墙在网关（token 类，submit 顺带查桶，零额外往返）；
- 本地桶承担速率类软限，短暂超发可容忍。

## 4. 执行点矩阵

| 准入点 | 查什么 | 失败语义 |
|---|---|---|
| 命令准入（会话 dequeue） | 主体突发桶（租约）、社交保护限 | denial + 429/错误形状 |
| gateway.submit | 各层体量配额 + 世界预算 + 供应商并发 | 按优先级降级（§5）；P0 返回配额错误 |
| 创建类命令 | 实体计数 + 存储配额 | denial（错误含当前用量） |
| 记忆写入/晋升 | 存储配额 | 暂停晋升（派生可滞后），配额恢复自动追平 |
| fork/沙盒 | 次数 + 独立 token 池 | denial |
| 插件/外部工具 | 每插件速率桶 | 熔断 + denial（M2） |

## 5. 耗尽语义（按优先级差异化）

- **P0 交互**：硬失败，返回结构化配额错误（`quota_exhausted`：桶、重置时间、retry-after）→ API 契约形状见 10 §4；
- **P2 环境闲聊**：**不硬停，自降**——配额水位接入饱和度广播 → τ_speak 上调、tick 拉长 → 角色自然"安静"，世界预算将尽时群体性"今日话少"；
- **P3 归纳**：延迟执行（派生滞后无害，恢复后追平）；
- **overage_policy**（配置旋钮）：`hard_stop | drop_tier | slow_down | borrow`（borrow = 从父节点未分配池临时借用，需父级允许）。

## 6. 记账与可解释性

```
quota.granted / allocated / revoked      —— 配额树结构变更（身份流）
cost.recorded(actor, on_behalf_of, tier, tokens, 引用)  —— 唯一记账事实（网关域）
```

- 每层消费视图 = 沿树聚合 cost.recorded（单次记账、多层视图，不重复记）；
- 重放还原任意时刻配额状态——"昨晚为什么被限流"精确到事件序列；
- 计费视图按链根聚合（on_behalf_of 已有），角色消费永远归账到人；
- `GET /v1/quotas/me` 返回各层余量与重置时间（10 §5）。

## 7. 商业化挂接

订阅档位 = 平台对链根的 `quota.granted`；升级/降级 = 追加/替换授予事件。计费系统未来只是这棵树的一个写入方，引擎无感知。
